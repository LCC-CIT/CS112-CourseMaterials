# CS 112 Course Materials

Course materials for CS 112, Introduction to Artificial Intelligence, at Lane Community College.
The site is published with GitHub Pages at https://lcc-cit.github.io/CS112-CourseMaterials/.

## Layout

- GitHub Pages publishes **only `/docs`** (Jekyll, `jekyll-theme-primer`, config in `docs/_config.yml`).
- Everything outside `/docs` (`Research/`, `LMS-Announcements/`, `Examples/`, `README.md`) is not part of the site.
- Lecture notes are in `docs/LectureNotes/`, assignments in `docs/Assignments/`, exercises in `docs/Exercises/`,
  and standalone web apps in `docs/Interactive/`.

## Conventions

- The course is **CS112**. Do not reintroduce "CS123" (the old course name) in text, links, or file names.
- The LMS is **Canvas** (`canvas.lanecc.edu`), not Moodle.
- Write links as `.html`, e.g. `CS112_Syllabus.html`, even though the source is `.md`. Pages renders every `.md` file,
  with or without front matter.
- Use relative links between pages. Never use local paths such as `D:\Repos\...`.
- Don't use file names with spaces.
- Keep images next to the notes that use them (`LectureNotes/Images/`, `Images/`).

## Sitemap

`docs/sitemap.xml` is generated by `jekyll-sitemap` on every Pages build. Don't create or edit it by hand;
a static `sitemap.xml` in `docs/` would stop the plugin from generating one.
To keep an unfinished page out of the sitemap, add `sitemap: false` to its front matter (add a front matter block if it has none)
and remove that line when the page is done. `_config.yml` already excludes `Assignments`, `Exercises`, `Images`, and `Interactive`.

## Link check

`.github/workflows/link-check.yaml` builds `/docs` with `actions/jekyll-build-pages` and runs lychee on the result.
It runs on every push and pull request, and fails on any broken link.

- Settings are in `lychee.toml` (accepts 200, 403, 429) and `.lycheeignore` (regex per line).
- Fix a broken link rather than ignoring it. Add to `.lycheeignore` only a link that works in a browser but fails in CI,
  and add a comment saying why.
- The workflow remaps our own published URLs to the local build, so a new page doesn't fail before the site has deployed.
- Links to Canvas course pages need a login and can't be checked. Link to public pages instead.
